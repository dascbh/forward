# fde-design-system

Read `.fde/spec/product-pipeline.md` for the stage, quality and provenance
contract. This is an agent command, not a shell executable or a new engine.

Discover tokens, kit, consumers, themes, glossary, reference screens and documented usage. Classify as absent, implicit, fragmented or explicit. Absent: bootstrap through fde-design. Implicit: extract observed semantics. Fragmented: consolidate duplicates with compatibility/migration. Explicit: reuse and revise demonstrated gaps. Discover and consolidate before officializing.

Use existing owners: fde-spec for discovery, hypotheses, requirements and
pre-UI UX blueprint; fde-design for flow/IA/wireframe and design QA;
fde-architecture for domain/data decisions and client ADRs. Design artifacts
remain design/product.md, foundation.md and patterns.md. Pin their revision
in consuming plans; record drift, migration/rollback and revisit triggers.
The skill grants no additional role write permissions.

Continue through the common request → discovery augmentation → hypotheses →
product spec → domain/data → architecture → backlog → implementation → deploy
contract. Use fde-backlog and fde-spec for existing vertical cycles and demand
specs, triage each slice, honor sign-off and frozen plans. Research and
self-criticism precede implementation and never replace isolated review.

Declare five UI dimensions, equivalent UX measures and a separate DS adherence
verdict before construction. Scale blueprint depth with size; backend-only
work records why UI/UX is not applicable. After UI, execute client-runnable
journeys and design QA, then validate UX with appropriately labeled evidence.
Unknown evidence is not pass. No new verifier flags exist.

Refresh affected Product Maps and check coverage; use existing review,
promotion and authorized cycle deploy plans. Handoffs cite artifacts and
revisions (I7); judgments cite existing principles (I8). New scope goes to
backlog; invalidated signed criteria/ADRs require replan. Never replace the
whole DS to solve one screen or invent speculative primitives.
