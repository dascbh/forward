# fde-inspect

An agent command, not a shell executable or a new engine.

Bound the feature/job. Use fde-survey and fde-map; sample operations by hand, inspect critical UI states and real-volume journeys. Record baseline UI/UX and separate DS adherence, source revisions and map coverage limits. Distinguish behavior from inferred intent. Preserve working contracts.

Use existing owners: fde-spec for discovery, hypotheses, requirements and
pre-UI UX blueprint; fde-design for flow/IA/wireframe and design QA;
fde-architecture for domain/data decisions and client ADRs. The skill grants
no additional role write permissions.

Continue through the common request → discovery augmentation → hypotheses →
product spec → domain/data → architecture → backlog → implementation → deploy
contract. Research and self-criticism precede implementation and never
replace isolated review.

Then follow `.fde/spec/product-pipeline.md`, shared with `fde-build`
and `fde-design-system`: stages, owners, criteria, provenance.
